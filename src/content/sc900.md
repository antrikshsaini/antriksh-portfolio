## 1. AZURE ACTIVE DIRECTORY (Azure AD / Microsoft Entra ID)

### What is Azure AD?
- Azure AD is a **cloud-based identity and access management (IAM) service** — it is **not** deployed to on-premises environments.
- It is **included with Microsoft 365 subscriptions** and is used by Microsoft 365 for identity.
- Azure AD is an **identity provider** that provides Single Sign-On (SSO), Multi-Factor Authentication (MFA), and Conditional Access — protecting against 99.9% of cybersecurity attacks.
- Azure AD is now referred to as **Microsoft Entra ID**.

### Azure AD Editions (4 tiers)
1. **Free** – Included with commercial online services (Azure, Dynamics 365, Intune, Power Platform).
2. **Office 365 Apps** – Included with Office 365 subscriptions.
3. **Premium P1** – Supports MFA and Conditional Access.
4. **Premium P2** – Supports everything in P1, plus **Privileged Identity Management (PIM)** and **Identity Protection**. *(Lowest tier needed for MFA + Conditional Access + PIM = **Premium P2**)*

### Key Azure AD Facts
- Azure AD tenants can have **multiple subscriptions**, but an Azure subscription can only be associated with **one Azure AD tenant**.
- You **can change** which Azure AD tenant a subscription is associated with.
- When an Azure subscription expires, the **Azure AD tenant is NOT deleted** — it remains and can be managed via a different subscription.
- All Azure AD license editions do **not** include the same features (False — features vary by tier).
- You do **not** need to deploy Azure VMs to host Azure AD — it is a cloud service (False statement).

### Roles in Azure AD
- **Global Administrator** has access to all administrative features in Azure AD.
- Azure AD supports **custom roles** in addition to built-in roles.
- An Azure AD user **can be assigned multiple roles** (not limited to one).
- **Custom roles** offer flexibility in granting access by allowing selection of specific permissions — they do **not** give unlimited access or eliminate the need for a license.

### Azure AD Tenants and Subscriptions
- An Azure AD tenant can have **multiple subscriptions**.
- A single Azure subscription can only be linked to **one** Azure AD tenant.

## 2. IDENTITY CONCEPTS

### Authentication vs. Authorization
- **Authentication** = Verifying **who you are** (e.g., entering a username and password). Users are authenticated **first** when signing into Azure portal.
- **Authorization** = Determining **what you can access** (checking roles and permissions). Happens after authentication.
- **Federation** = A collection of domains that have established a **trust relationship** between organizations. Typically includes authentication and authorization. Guest/external users appear in the directory.

### Hybrid Identity
- Hybrid identity uses accounts originating in on-premises **Active Directory Domain Services (ADDS)** with a copy synchronized to **Azure AD**.
- Synchronized using **Azure AD Connect** — runs on an on-premises server, detects changes in ADDS and syncs to Azure AD.
- Azure AD Connect provides **password hash synchronization** (PHS) — syncing a hashed version of user passwords.
- Hybrid identity does **not** require two Microsoft 365 tenants (False).
- On-premises ADDS is the **authoritative source** for account information in hybrid identity.
- Most changes **flow one way**: on-premises → Azure AD.

### Authentication Methods for Hybrid Identity
| Method | Key Point |
|--------|-----------|
| **Password Hash Synchronization (PHS)** | Users sign in with same username/password as on-premises. Provides **highly available cloud authentication** even if on-premises AD goes down. |
| **Pass-Through Authentication (PTA)** | Authenticates directly against on-premises AD. Does **not** store passwords in Azure AD. |
| **Federated Authentication** | Authentication handled by a separate identity provider (e.g., ADFS). |

### Service Principals and Managed Identities
- When an application is **registered in Azure AD**, a **service principal** object is automatically created.
- **Managed Identity** = an automatically managed identity for Azure resources. No credentials to manage, no extra cost. Best choice when connecting an app to Azure resources without managing credentials.
- **System-assigned managed identity**: tied to one specific resource; deleted when the resource is deleted.
- **User-assigned managed identity**: created independently and can be shared across resources.

### Azure AD B2B vs B2C
- **Azure AD B2B (Business-to-Business)**: Enables **collaboration with external users** (partners, suppliers, vendors). External users appear as **guest users** in the directory. Allows sharing of apps and resources with external organizations.
- **Azure AD B2C (Business-to-Consumer)**: Handles **authentication for consumer-facing apps**. Enables external users to sign in using social/enterprise identities. Custom branding can be applied. B2C users are managed in a **separate directory** from the main Azure AD organization.

## 3. MULTI-FACTOR AUTHENTICATION (MFA)

### What is MFA?
- Requires **two or more** of the following authentication factors:
  - **Something you know** – password or PIN
  - **Something you have** – phone, hardware key, security token
  - **Something you are** – biometric (fingerprint, face scan)
- A password alone is "something you **know**."

### Azure AD MFA Methods
- ✅ **Text message (SMS)**
- ✅ **Microsoft Authenticator app** (push notification or code)
- ✅ **Phone call**
- ❌ Email verification (not an MFA method)
- ❌ Security questions (not an MFA method for MFA, used for SSPR)

### Self-Service Password Reset (SSPR) Methods
- Mobile app notification, **text message to a phone**, **security questions**, certificate (not picture password).

### Security Defaults in Azure AD
When enabled, security defaults enforce:
- **All users must register for Azure AD MFA**.
- **Administrators must always use MFA**.
- Users prompted for MFA when necessary.
- Legacy authentication protocols are **blocked**.
- Access to the Azure portal is protected (privileged activities).

## 4. PASSWORDLESS AUTHENTICATION

### Methods
- **Windows Hello for Business** ✅ (passwordless)
- **FIDO2 security keys** ✅ (passwordless)
- **Microsoft Authenticator app** ✅ (passwordless)
- Software tokens ❌ (NOT passwordless — still require a password)

### Windows Hello for Business
- Replaces passwords with **strong two-factor authentication** tied to a device.
- Authentication methods supported: **Fingerprint**, **Facial recognition**, **PIN**.
- Biometric data is stored **locally on the device only** — never sent to external devices or servers, no single collection point for attackers.
- Authentication info does **not** sync across multiple devices.
- Uses certificate or asymmetrical key credentials bound to the device.

### Azure AD Password Protection
- Detects and blocks **known weak passwords** and their variants.
- Allows custom banned password lists for organization-specific terms.
- Purpose: **Prevent users from using specific weak words** in passwords.

## 5. ZERO TRUST

### Core Principles (3 Guiding Principles)
1. **Verify Explicitly** – Always authenticate and authorize using all available data points.
2. **Use Least Privilege Access** – Limit user access with just-in-time and just-enough access.
3. **Assume Breach** – Minimize blast radius; verify every request as if from an uncontrolled network.

### Key Points
- Zero Trust is a **security strategy/approach**, not a product or service.
- The model does **NOT** assume that a firewall secures the internal network (False — that's the old perimeter model).
- Uses **identity as the primary security boundary** (not the network/physical location).
- "Never trust, always verify" — regardless of where the request originates.
- Conditional access policies are the heart of Zero Trust's **identity-driven control plane**.

## 6. CONDITIONAL ACCESS POLICIES

### What is Conditional Access?
- Brings **signals together** to make access decisions and enforce organizational policies.
- At the heart of the **identity-driven control plane** in Azure AD.
- Policies are enforced **after first-factor authentication** is completed (NOT before).
- Can be applied to **all users**, including **global administrators** and **B2B guest users**.

### Signals Used by Conditional Access
- **User or group membership**
- **Device state/platform** (Android, iOS, Windows, etc.)
- **Location** (IP address / named location)
- **Application being accessed**
- **Real-time sign-in risk** (via Azure AD Identity Protection)

### What Conditional Access Can Do
- ✅ Require MFA for specific users or applications
- ✅ Block or grant access based on location
- ✅ Block risky sign-in behaviors
- ✅ Require compliant/managed devices
- ✅ Can be used to restrict Intune-managed devices from corporate resources
- ❌ Does **not** always enforce MFA — it depends on the policy configuration
- ❌ Cannot add users to Azure AD roles
- ❌ Is **not** a first line of defense against DoS attacks

### Session Controls
- Enable **limited experiences** within specific cloud apps (e.g., block download of sensitive info, prevent copy/paste).

## 7. PRIVILEGED IDENTITY MANAGEMENT (PIM)

### What is PIM?
- A service in Azure AD that enables you to **manage, control, and monitor** access to important resources.
- Provides **time-based and approval-based role activation** (Just-In-Time access).
- Mitigates risk of excessive, unnecessary, or misused permissions.
- Use case: Provide a user with a **2-hour window** to complete an administrative task.
- Requires **Azure AD Premium P2**.

### Key PIM Features
- Just-in-time privileged access
- Request approval workflows
- Fully integrated access reviews
- Ability to identify, uncover, and prevent malicious privileged role activities in real time.

## 8. AZURE AD IDENTITY PROTECTION

### What is Identity Protection?
- Automates **detection and remediation** of identity-based risks.
- Can detect whether **user credentials were leaked** to the public.
- Can invoke **MFA** based on a user's risk level.
- Can **block sign-in attempts** or require password changes.
- Works with Conditional Access policies as an extra protection layer.
- Can **export risk detections** to third-party utilities (SIEM tools).
- Does **NOT** add users to groups based on risk level (False).

- Can **automatically remove** users that no longer require group membership.
- Allows regular review of user access to ensure only the right people have continued access.

## 10. MICROSOFT DEFENDER PRODUCTS

### Microsoft Defender for Identity
- A **cloud-based** security solution that leverages **on-premises Active Directory (ADDS) signals** to identify, detect, and investigate:
  - Advanced threats
  - Compromised identities
  - Malicious insider actions
- Helps SecOps detect advanced attacks in hybrid environments.
- Monitors user/entity behavior using learning-based analytics.
- Source of signals: **on-premises Active Directory Domain Services (ADDS)** (not Azure AD Connect or Azure AD directly).

### Microsoft Defender for Endpoint
- Provides **Endpoint Detection and Response (EDR)** capabilities.
- Key capabilities:
  - ✅ **Automated Investigation and Remediation**
  - ✅ **Attack Surface Reduction (ASR)** — includes **Network Protection** as a first line of defense.
  - ✅ Advanced hunting
- Can protect **Android devices** and **Azure VMs running Windows 10**.
- Does **NOT** protect SharePoint Online content from viruses (that's Defender for Office 365).
- Network protection: protects devices from internet-based events; an **attack surface reduction capability**.
- Managed from the **Microsoft 365 Defender portal**.

### Microsoft Defender for Office 365
- Safeguards against malicious threats in **email messages, links, and collaboration tools** (Teams, SharePoint, Outlook).
- Can **scan email attachments** and only forward if free from malware.
- Includes **Attack Simulation Training** (Plan 2 or Microsoft 365 E5) — runs realistic phishing/cyber attack simulations to train employees.
- Provides real-time threat views and **threat explorer** for threat hunting.

### Microsoft Defender for Cloud Apps (formerly Microsoft Cloud App Security)
- A **Cloud Access Security Broker (CASB)**.
- Use cases:
  - ✅ **Discover and control Shadow IT** (cloud apps not authorized by IT)
  - ✅ Protect sensitive information hosted anywhere in the cloud
  - ✅ Prevent data leaks to non-compliant apps and limit access to regulated data
  - ✅ Can use **conditional access policies to control sessions in real time**
- Does **NOT** provide secure connections to Azure VMs or pass-through authentication.

### Microsoft Defender for Cloud (formerly Azure Security Center)
- Provides **Cloud Security Posture Management (CSPM)** and **Cloud Workload Protection**.
- Available for **all Azure subscriptions** (CSPM is free).
- Can evaluate security of workloads in Azure **or on-premises** (unified security management).
- Provides **Secure Score** — measures overall security health of an Azure subscription.
- Enhanced security features:
  - **Hybrid Security**: unified view of security across on-premises and cloud workloads.
  - **Adaptive Application Controls**: intelligent allow-listing of known safe applications; reduces exposure to brute force attacks on management ports.
  - **Just-in-Time VM Access**: locks down inbound traffic, reducing attack surface.
  - Vulnerability scanning for VMs.
  - Threat protection alerts.
- **Network map**: continuously monitors network security status.
- Provides threat detection for **Azure SQL Managed Instances**.
- The free tier provides: **Secure Score** only (not JIT VM access, vulnerability scanning, or threat alerts).

## 13. NETWORK SECURITY

### Network Security Groups (NSGs)
- Filter **inbound and outbound** network traffic to/from Azure resources in a virtual network.
- Can deny inbound traffic **from the internet** ✅
- Can deny outbound traffic **to the internet** ✅
- Can filter traffic based on **IP address, protocol, and port** ✅
- Can be associated with: **Virtual network subnets** and **Network Interface Cards (NICs)**.
- You can associate **zero, one, or more NSGs** to each virtual subnet or NIC.
- One NSG can be associated with **multiple** subnets and NICs.
- NSGs apply to **intra-subnet traffic** in a virtual network.

### Azure Firewall
- Provides **Network Address Translation (NAT)** services (SNAT and DNAT).
- Can protect **Azure virtual machines** and **Azure virtual networks**.
- Does **NOT** protect Azure AD users, Exchange Online inboxes, or SharePoint Online sites.

### Azure Bastion
- Provides **secure, seamless RDP/SSH connectivity** to Azure VMs **directly from the Azure portal** over TLS.
- You do NOT need a separate RDP client — you use the **Azure portal** (or the remote desktop connection client in some questions).
- You can create **one Azure Bastion per virtual network**.
- Provides secure access to **Azure virtual machines only** (not Azure Files, SQL Managed Instances, etc.).

### Azure DDoS Protection Standard
- Protects **virtual networks**.
- Can protect up to **100 resources** without additional cost.

### Defense in Depth
- Uses a **layered approach** to security — multiple layers of protection throughout network infrastructure.
- Each layer provides protection so that if one is breached, the next prevents unauthorized access.
- Does NOT rely on a single perimeter.

## 14. ENCRYPTION & DATA PROTECTION

### Encryption Basics
- **Encryption**: The process of encoding information (plaintext → ciphertext). Only authorized parties can decipher it back.
- **Encryption at rest**: Encrypting data stored on disk. Example: **Encrypting a VM disk**. Uses symmetric encryption.
- **Encryption in transit**: Encrypting data as it moves. Examples: HTTPS, site-to-site VPN, encrypted email.

### Encryption Types in Azure
| Type | Use Case |
|------|----------|
| **Azure Disk Encryption** | Encrypt **Windows and Linux IaaS VM disks** in Azure. |
| **Transparent Data Encryption (TDE)** | Protects **Azure SQL Database and Azure Data Warehouse** from malicious activity. Real-time encryption/decryption. |
| **Azure Storage Service Encryption** | Automatically encrypts data at rest in **Azure Blob Storage and Azure File Shares**. |
| **Always Encrypted** | Used for highly sensitive data in SQL databases. |

### Hashing
- Ensures **data has not been tampered with in transit** (data integrity).
- Maps source data to a fixed-size value using a mathematical function/algorithm.
- Recipients compare the hash value to verify the file was not tampered with.

### Digital Signatures
- **Signing** a document requires a **private key**.
- **Verifying** a digitally signed document requires the **public key** of the signer.
- The private key is used only by the signer; the public key validates the signature.

### Azure Key Vault
- A **cloud service for storing application secrets** (keys, passwords, certificates, tokens).
- For certificates: facilitates **provisioning, management, and deployment of public and private SSL/TLS certificates** for Azure resources.
- Encryption for VM disks in Azure uses **Azure Disk Encryption** (not Key Vault directly for VMs).

## 16. SHARED RESPONSIBILITY MODEL

### Who is Responsible for What?
- **Microsoft is always responsible for**: Physical hardware, physical network, physical datacenter.
- **Customer is always responsible for**: Data, information, accounts and identities, devices (mobile phones/PCs).
- In **SaaS** (e.g., Microsoft 365): Customer is responsible for **accounts and identities**, and data. The cloud provider patches the OS and apps. Applying service packs to SaaS apps is **NOT** the customer's responsibility.
- In **IaaS** (e.g., Azure VMs): Cloud provider manages **physical network**. Customer manages OS, apps, data.
- For **ALL cloud types**: Managing **security of information and data** is always the **customer's responsibility**.

## 19. INFORMATION PROTECTION & DATA LOSS PREVENTION

### Sensitivity Labels
- Used to **classify and protect** documents and emails.
- Can: encrypt documents ✅, add headers/footers ✅, add watermarks ✅, apply markings to files ✅.
- Can be applied **manually by users** or automatically.
- Only **one sensitivity label** can be applied to a document/email at a time (cannot apply multiple labels to the same file).
- A sensitivity label policy can contain **multiple labels**.
- You can specify a **default label** to be applied to all items in a container.
- Can be used to **classify content without adding protection settings**.

### Data Loss Prevention (DLP)
- Helps prevent **unintentional sharing of sensitive information**.
- Examines email and files for sensitive information (credit cards, etc.).
- Can: log events, display policy tip warnings to users, actively block email/file sharing.
- Use DLP policies to **restrict users from sending emails containing sensitive data** (e.g., customer credit card numbers).
- DLP policies can **display policy tips to users** about to violate policies ✅.
- DLP policies can **protect OneDrive documents** containing sensitive info ✅.
- DLP does NOT enable disk encryption or apply security baselines.

### Data Classification Tools
| Tool | Purpose |
|------|---------|
| **Trainable Classifiers** | Use **AI/machine learning** to categorize data. Can be pre-trained (by Microsoft) or custom. |
| **Sensitive Information Types** | Use **regular expressions** and keyword matching. |
| **Exact Data Match** | Match specific data exactly. |
| **Fingerprint Classifier** | Based on document fingerprinting. |
| **Pre-trained Classifiers** | Use to identify specific document types like **employee resumes**. |
| **Content Explorer** | View all items with applied labels across the organization. |
| **Activity Explorer** | View a **historical view** of labeling activity (labels applied/changed). |
| **Content Search** | Find emails and documents containing specific keywords (e.g., across SharePoint, Exchange, OneDrive). |

### Information Barriers
- A compliance solution that **restricts two-way communication and collaboration** between groups/users.
- Works in **Microsoft Teams, SharePoint Online, and OneDrive for Business**.
- Use case: Restrict Teams chats between two departments, prevent search/messaging between users.
- Used in **highly regulated industries** to avoid conflicts of interest.

### Information Protection Solution (Microsoft 365 Compliance Center)
- Protects **sensitive data from being exposed to unauthorized users**.

## 23. MICROSOFT PRIVACY PRINCIPLES (6 Principles)

1. **Control** – Put customers in control of their privacy with easy-to-use tools and clear choices. Individuals can access, modify, or delete data. *(Applies to individuals' use of and access to their personal data.)*
2. **Transparency** – Be transparent about data collection and use so you can make informed decisions.
3. **Security** – Protect data through strong security and encryption.
4. **Strong Legal Protections** – Respect local privacy laws; fight for privacy as a fundamental human right.
5. **No Content-Based Targeting** – Never use email, chat, files, or personal content to target ads.
6. **Benefits to You** – When data is collected, use it to benefit the user and improve their experience.

- **Shared responsibility is NOT** a privacy principle of Microsoft.
- Privacy principles help you make choices about how and why Microsoft data is collected and used.
